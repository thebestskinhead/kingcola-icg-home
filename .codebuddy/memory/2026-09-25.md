## SMTP 密码改为「存数据库」（用户要求：密码同样保存在数据库中）
用户原话「神了，密码同样保存在数据库中大哥」—— 即不要只让密码走环境变量，后台要能直接填、存进库。

- 契约：`shared/mail.ts` 的 `SmtpConfig` 加 **`password?: string`**（D1 里存的是密文；`DEFAULT_SMTP_CONFIG.password = ''`），
  新增 **`publicSmtpConfig(mail)`** —— 返回 `{ ...mail, password: undefined }`，`JSON.stringify` 会丢掉该键，
  所以前端拿到的 mail **连 password 字段都没有**，也就不可能把空值误提交回去。
- 加密：`worker/lib/crypto.ts` 新增 `encryptSecret` / `decryptSecret` / `isEncryptedSecret`：
  HKDF(SHA-256, info=`kingcola.secret`) 派生 AES-GCM 密钥，密文格式 `enc$<iv b64url>.<密文 b64url>`；
  密钥来自 **`SESSION_SECRET`**（不新增环境变量）。**解密失败返回 null 而不抛异常**（换 secret 时不炸接口）。
- 取值逻辑：`worker/lib/mailer.ts` 新增
  `mailPasswordOf(env, config)`（**数据库优先、`SMTP_PASSWORD` 兜底**）、
  `mailPasswordSourceOf()`（`database|env|none`，给后台提示）、
  `resolveMailPassword()`（密文→明文，失败回退并 warn）、`encryptMailPassword()`（保存前加密）；
  `isMailConfigured()` 改为「username 为空就当无需认证」。
- 路由：`routes/config.ts` 的 `resolveRuntimeConfig` 读 KV/D1 后**在内存里解密** ——
  ⚠️ **写进 KV 缓存的是未解密的密文版**，千万别把明文密码放进 KV；
  新增 `publicRuntimeConfig()`，公开接口 `/api/config/runtime` 与后台 `GET /api/admin/config` 都走它；
  `updateAdminConfig` 对密码做**三态**处理（**不带 password 键 = 不修改；空串 = 清除；有值 = 更新**），
  并且先 `delete restRuntime.mail` 再 spread（否则提交上来的明文会进落库对象）；返回体带 `mailPasswordSource`。
- 后台：`src/admin/SettingsPage.tsx`「邮件通知」加密码输入框（`type=password`，placeholder 提示「已保存——留空表示不修改」）
  +「清除已保存的密码」链接，改成独立的 `saveMail()`；状态文案按 `mailPasswordSource` 分三种。
  `endpoints.ts` 的 `AdminConfigResponse.mailSecretConfigured` → **`mailPasswordSource`**，`adminUpdateConfig` 返回体同步。

### 端到端验证（含真实 AUTH，已全部通过）
临时写了个**要求 AUTH LOGIN 的 Python 假 SMTP**（用户名/密码不匹配就拒信）：
1. PUT 配置（password=`super-secret-token`）→ **D1 查出的是 `enc$SuNJ99xkf8zGGMj9.C1LAF…` 密文**，不是明文；
2. `POST /api/admin/mail/test` → **200**，假服务器日志 **`AUTH user=studio@example.edu.cn ok=True`**
   （证明密码确实被解出来并用在了认证上）；

5. PUT **空串** → `source=none` + **400 NOT_CONFIGURED**，D1 里 `pw` 变空串（清除生效）。

## ⚠️ 招新模块方向修正（另一并行会话）· 从「时间驱动」改为「事件驱动」

> 本日早期关于招新的大段记录（commit `d264402`…`7078a14` 七笔）已被并行会话的 SMTP 记录覆盖，

用户否定阶段性成果：阶段分类的大方向对，但 ① 准备阶段只该填**报名开始时间**，其余时间在前一阶段配、
**所有事件的结束都由管理员手动触发**；② 名单与看板职责重复；③ 要多级页面 + 时间线导航、进入默认当前阶段；
④ **「事件进行时」与「事件结束后」被混在一个面板里**（最关键的批评）；⑤ 看不到签到、没签完就能录成绩。

**事件枚举与拓扑序**（每事件 = 配置 → 进行中 → 结束（手动）→ 结束后）：
E0 备招（名称 + 报名开始时间）→ E1 报名（收表/替换/补录/未通过初筛/**配置笔试场次**）→
E2 笔试（二维码/签到/补签 → **结束笔试** → 标记缺考+录成绩+**配置面试场次**+生成面试名单）→
E3 面试（同构）→ E4 答辩（同构）→ E5 转正（等确认/催确认 → **关闭本届**）→ 归档。
要删的时间门禁：applyEnd / writtenEnd / absentGraceHours / onboardDeadline / autoClose / Cron 兜底。
遗留真 bug：`STAGE_RESULTS.defense` 缺 `attended` 而答辩签到会写它。

**四条已确认决策**：① 结束动作 = 顺带收尾 + 二次确认（结束笔试→自动标记缺考，弹窗写明人数）；
② 报名的结束拆两步：先「结束报名」（只关入口，名单还能改）再「确认名单」（发邀请函）；
③ 导航 = 顶部时间线（备招→报名→笔试→面试→答辩→转正→归档），当前高亮、进入默认当前阶段、未来阶段可看但锁定；
④ **砍掉看板**，统计进时间线当前阶段页顶部的摘要条；名单保留为全局搜索/导出/批量工具。

### 三轮问答后的最终模型 v3（极简，全部事件驱动）
- **时间字段全删**：applyEnd / writtenAt / writtenEnd / writtenPlace / interviewAt / interviewPlace /
  defenseStart / defenseEnd / onboardDeadline / absentGraceHours / autoAbsent / autoClose / Cron 兜底。
  周期配置只剩：本届名称 + **step 推进指针**。备招阶段只剩：名称 + 邮件模板 + 4 个 QQ 群号。
- **报名开始也手动**：备招页点「开启报名」（连报名开始时间都不填）。
- **场次概念整体删除**：`recruit_sessions` 表、场次 CRUD/路由/UI、applications 的 *_session_id 列全删。
  **签到二维码绑阶段**（笔试/面试/答辩各一张），**可被创建无数次但创建新码会自动作废旧码**（同时至多一张有效），
  **生成时自选有效期（小时）**，可手动作废。
- **所有邀请信不含时间/地点/场次**，一律「看 QQ 群通知」。**QQ 群分 4 个**：笔试群 / 面试群 / 预备成员群 /
  正式成员群 —— 站点设置里各填一个群号，模板分别用 {writtenGroup} / {interviewGroup} / {probationGroup} /
  {formalGroup}。面试通过通知里的预备期起止段落删除。
- **补签**：进行中可补签；**结束后也能补签并自动撤销「缺考」**。
- **补录**只有两个入口，字段与官网报名完全一致（邮箱/手机/QQ/报名表全必填）：
  ① 报名进行中 + 结束报名后（进报名名单，确认名单时可被勾选）；
  ② 笔试进行中 + 结束笔试后（**录入即视为已参加笔试，无需签到**，不会被缺考扫描误伤）。
  面试 / 答辩阶段**没有**补录。
- 各阶段面板：进行时（二维码/补签/补录）与结束后（录成绩/定名单）同页切换显示，结束前只见进行时。
