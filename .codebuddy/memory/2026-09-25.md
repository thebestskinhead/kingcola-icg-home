## 招新系统设计复审（用户要求「先模拟完整招聘流程再定结构」，结论已定，实现中）
用户指出我上一轮问的问题不在关键点上，并给出三条硬约束：
1. **当前阶段不可能出现的操作** → 隐藏或折叠；
2. **同一阶段的「操作」与「数据」** → 分开查看；
3. **同一阶段的操作** → 能在一个标签页内全部查看。

**我按「管理员逐时点要做什么」模拟了整届流程**（备招 → 报名中 → 确认笔试名单 → 笔试当天签到 → 改卷录成绩 → 生成面试名单+标记缺考 →
面试签到 → 确认录取 → 预备期无事可做 → 答辩签到 → 确认答辩 → 转正期催确认 → 关闭归档），
推出三个关键结论：
- **同一阶段在不同时刻能做的操作完全不同**（笔试阶段「考试中」只有签到/补签，「改卷时」只有成绩/生成名单/标记缺考）→
  必须**按前置条件裁剪操作卡**，不能平铺。
- **前置条件服务端已经算好了**：`GET /api/admin/recruit/auto?task=…` 的 `preview.blocked` 就是「为什么现在不能做」的人话文案，
  `preview.items.length` 就是影响人数 → **操作卡的展开/折叠不需要新逻辑**，直接复用它驱动 UI。
- **「预备期无事可做」是需要显式表达的真实状态**（说明卡），否则管理员会反复刷新找按钮。

**结构定案**：阶段为主轴，每个阶段页签内 **操作区（上，卡片式，可按前置折叠）+ 数据区（下，只读为主）** 两块分开；
看板按周期三态变脸（未开始=备招检查清单 / 进行中=漏斗+待办 / 已结束=本届总结+存档）；
「关闭本届」只留在周期页（自动化页不再重复）。

**同时要修的 4 个问题**（复审审出来的）：
- P1 **真 bug**：`STAGE_RESULTS.defense` 没有 `attended`，但答辩签到会写 `attended` → 校验与写入不一致，要补上并加断言。
- P2 `apply/failed`（未通过初筛）是死状态、且没有邮件模板 → 「确认笔试名单」改成**可勾选**（未勾的判未通过并发告知信）。
- P3 `mark_absent` 静默淘汰 → 补一封缺考告知信。
- P4 `declined`（学生婉拒）无学生入口 → `/join` 进度页与邀请函页各加一个自助出口。
- 邮件模板因此从 7 条增到 9 条（+ 未通过初筛 + 缺考）。
- 另有两处小缺陷：成绩录入页列了已结束的人；看板待办卡跳转丢了 `task` 参数。
