**我按「管理员逐时点要做什么」模拟了整届流程**（备招 → 报名中 → 确认笔试名单 → 笔试当天签到 → 改卷录成绩 → 生成面试名单+标记缺考 →

**两个刻意定下的语义**（都写进了注释）：
1. **有场次时由场次反写周期**：首场 → `writtenAt`/`writtenPlace`，末场结束 → `writtenEnd`
   （它是「缺考标记」的起点，必须与场次一致）；没有场次就保留手填的兜底值。
2. **重新签发二维码 = 旧码立即作废**：同一场次同时只保留一张有效码。理由是二维码会被拍照转发，
   重发往往正是因为旧码泄了 —— 只追加不作废的话，作废按钮形同虚设。
   另：过期时间取 `max(现在+TTL, 场次结束时间)`，避免拖堂时同学签不了。

**踩到并修掉的两个坑（自检抓出来的）**：
- `rowToSession` 按**字段名**读行，而行键是 **SQL 列名**（`starts_at`）→ 时间字段全读成空串，
  表现是 5 项失败、`writtenEnd` 变成 `1970-01-01T08:00`（epoch 0）。加了 `SESSION_COLUMN_OF` 映射。
  **凡「显式列映射」的仓储都应自觉配一张 字段↔列 表**，`worker/lib/applications.ts` 就是这么写的。
- `applications` 的 `COLUMNS` 没同步新增的 `written/interview/defense_session_id` 与 `source` →
  `updateApplication` 的白名单查不到列名会**静默丢弃**该字段（签到写的场次归属丢掉）。
  已在 COLUMNS 补齐，并让 `createApplication` 显式写入 `source`。

- 锁死条件：`isApplyOpen()`（确认笔试名单后报名通道关闭）+ 双保险 `existing.stage !== 'apply'` →
