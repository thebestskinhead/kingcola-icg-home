## 成员表读写审计（用户要求：「确保创建时所有字段均会填写，或走完该函数所在的工作流后能完成全部字段读写」）

**审计结论**：`members` 的写入只有三个入口（全仓无裸 SQL，都走 `shared/resources.ts` 元数据）：
① 后台通用 CRUD `POST|PUT /api/admin/content/members` → `admin-content.ts` → `repo.ts`；
② 学生邀请函转正 `POST /api/applications/invite/:token` → `applications.ts: confirmInvite`；
③ 演示数据 `seed-content.ts` → `insertSeedEntity`。
读取只有 `listEntities` / `getEntity`（`columnList` = `id` + 全部字段列，`rowToEntity` 全量解码）→ 读侧本来就无遗漏。

**原来的缺口**：
1. `entityToRow` 遇到没提交的 key 直接跳过 → 写不写满整行全看调用方，缺的列靠建表 SQL 的 DEFAULT 兜底；
2. `confirmInvite` 的成员对象**漏了 `destination`**；
3. `direction`（在组）/`destination`（已毕业）这对互斥字段**从来没有被校验**过，两项可以同时为空；
4. `createEntity` 非自增分支返回 `{ id, ...input }` —— **新增接口的返回值不含补上的默认值与时间戳**，与「读」不同形。

**改动**（`npm run typecheck` + 改动文件的 eslint 均通过）：
- `worker/lib/repo.ts`：`createEntity`/`insertSeedEntity` 改成先 `{ ...defaultEntity(def), ...input }` 再 `entityToRow`
  → INSERT 覆盖**全部列**；非自增分支改为**回读整行**返回（复用 `getEntity`），新增接口形状与读一致。
  `updateEntity` **刻意不动**（仍只写提交上来的列，这样部分更新不会把别的字段清空）。
- `shared/resources.ts`：`direction`/`destination` 加 `requiredWhen`（与 `showWhen` 同条件）→ 在组必填负责方向、已毕业必填毕业去向。
- `shared/types.ts`：`Member` 的 `destination`/`avatarUrl`/`sortOrder` 由可选改**必填**（D1 这三列都是 NOT NULL DEFAULT，读出来必然有值，原来的 `?` 是错的）。
- `shared/seed.ts`：种子改用 `SeedMember`（三字段可选）+ `map` 补默认值，导出仍是完整的 `Member[]`。
- `worker/routes/applications.ts`：`confirmInvite` 显式写 `destination: ''`（整行齐全），并新增 `direction` 必填校验（与 requiredWhen 同一条规则）。
- `src/sections/InviteSection.tsx`：负责方向加 `*`、提交前本地校验、加一行提示。
- `src/admin/ContentPage.tsx`：提交前用**同一个** `validateEntity` 先本地校验（不再白跑接口拿 400）；必填星号对 `requiredWhen` 也生效。

**以后照着改的口径**：读 = 全列；创建 = 默认值补全后整行写、并回读整行；更新 = 只写提交的列；
校验 = 唯一 `validateEntity`；互斥字段 = `requiredWhen` + `showWhen` 同条件（已同步进 `MEMORY.md` 的架构约定）。

**顺带**：`MEMORY.md` 超限被截断，按规则整篇重写了一遍（合并招新章节、删掉已作废的场次/自动流程/Cron/时间窗描述）。
