## 报名材料审核 + 报名结束后的进度入口（用户提的一大组需求）

用户原话三块：① 报名阶段后台要能审核每份材料是否合法，提供「接受 / 驳回」，驳回后发信要求同学按理由改；
② 前台「加入我们」在报名关闭后要提示「报名已结束」，但下面要有**扫码登录按钮**给已报名同学看进度；
③ 报名阶段同学能看材料状态、重新上传/修改材料（后台要能加新报名表、删旧表并改库里的路径）。

**落地**：
- 迁移 `0010_recruit_material_review.sql`：`applications` 加 `material_status` / `material_reason` /
  `material_reviewed_at` + 索引。`shared/recruit.ts` 加 `MaterialStatus` / `MATERIAL_STATUS_LABELS` /
  `isMaterialApproved` / `MATERIAL_REASON_MAX`。
- 第 8 条邮件模板 `material_rejected`（「材料驳回通知」，变量 `{rejectReason}`）—— 契约五处常量表 + 
  `buildNoticeVars` 一处；设置页/补发下拉/日志都是循环驱动，自动生效。
- 后端：`PUT /api/admin/applications/:id` 支持 `material` / `materialReason`（**用 `!== undefined` 判断**，
  因为空串 = 退回待审核是合法取值）；驳回**自动发信**；批量 `approve_material` / `reject_material`（逐人发信，
  响应带 `mail` 汇总）；新增 `materialReviewGate()`（只在 apply / apply_review 可用）与
  `validateRejectReason()`（理由必填、≤200 字）。
- **门禁**：`recruit-cycle.ts` 的 `promote()` 里，`plan.stage === 'apply'` 时校验
  `isMaterialApproved` → 未通过的人不能被勾进笔试（409 `MATERIAL_NOT_APPROVED`，报出姓名学号）。
  刻意只作用于「报名 → 笔试」：过了笔试再拿材料卡人没意义（现场补录到笔试的人更不该被拦）。
- **重传即重置**：`worker/routes/applications.ts` 的替换分支与后台替换报名表，都把
  material 三列清空 → 回到待审核（旧结论是针对旧文件给的）。
- 后台 UI：名单页加「材料审核」筛选行 + 材料列徽标 + 行内「通过 / 驳回」+ 批量条两个按钮 +

  报名页与「确认笔试名单」页加 `materialBar()` 进度条（待审核 N / 已通过 N / 已驳回 N）。
- 前台：`JoinSection` **重排分支** —— 未登录分支提到最前（原来 `!applyOpen && !hasApplication` 抢在前面，
  报名一结束未登录者就没有登录入口了，只能干看着）；关闭态文案改「报名已截止」+ 按钮改
  「扫码登录，查看我的进度」；被驳回且报名未结束时默认直接渲染「改材料」表单（`reupload`），
  可切回进度（`showProgress`）；联系方式从已有记录预填；`submit(forceReplace)` 走 `?replace=true`。

## Bug：配好群号后，设置页仍显示「还没配置」（用户截图报的）

**现象**：后台「设置 → 邮件模板 → 可用变量」里 `{cycleName}` 显示 `调试用2`（说明本届配置读到了），
但 `{writtenGroup}` 等四个群号全是「还没配置（发送时保持原文）」。查库确认
`site_config['recruit'].cycle.groups` 里四个群号**都存着** —— 也就是说**只有预览在骗人**。

**根因**：`RecruitSettingsView` 的 `previewVars` 写的是 `...admin.cycle.groups`，
而 `groups` 的键是**短名**（`written` / `interview` / `probation` / `formal`），
模板令牌却是 `{writtenGroup}` —— 键名对不上，`variableValue()` 取到 undefined 就报「还没配置」。
发信侧（`worker/lib/recruit-mail.ts` 的 `buildNoticeVars`）一直是显式映射，所以真信是对的。

**修法（不只是补上键名）**：在 `shared/recruit.ts` 新增 **`cycleMailVars(cycle)`**，
把「本届配置 → 模板变量名」收敛成唯一一份；worker 发信与后台预览都改成用它 ——
两边不可能再各写一套（同类 bug 上次是 `{rejectReason}` 那批变量清单，也是靠共享常量避免的）。

顺带：
- `{rejectReason}` 在变量清单里改成显示「驳回时由管理员逐次填写」（它本来就是逐次填的，不是「没配置」）；
  预览给它一个示例理由，让「材料驳回通知」的预览有内容可看。
- 自检加一条断言「本届变量被渲染成实际群号（不是原样保留）」：发一封主题带 `{writtenGroup}` 的群发通知，
  再从发信日志里断言主题里是 `710000001` —— 把「真发信会替换」这件事钉住（103 项全绿）。
