## 查证：Cloudflare 能不能直接连 Git 仓库构建（2026-09-29，用户提问）

**可以** —— 官方叫 **Workers Builds（Git integration）**，GitHub / GitLab 都支持，官方文档 2026-09-22 更新。
新建：Create application → Import a repository；已存在的 Worker：**Settings → Builds → Connect**。

对**本项目**的要点（已核 `docs/HANDOVER.md` + 当前 `wrangler.toml`）：

| 项 | 结论 |
|---|---|
| Build command | `npm run build`（= `tsc -b && vite build`，产出 `dist/` 给 `[assets]` 用） |
| Deploy command | 默认 `npx wrangler deploy` 即可（读 `wrangler.toml`） |
| Preview command | 默认 `npx wrangler preview`（非生产分支）；**Preview 会连到同一套生产 D1/KV/R2**（`[env.preview]` 只覆盖了 name 与 SSO 基址），要么别开、要么配独立资源 |
| ⚠️ 前置① | `wrangler.toml` 现在还是占位符（`REPLACE_WITH_D1_DATABASE_ID`、`REPLACE_WITH_KV_NAMESPACE_ID`），不换成真实 ID 第一次构建必失败 —— **只有用户能做** |
| ⚠️ 前置② | Dashboard 里的 Worker 名必须与 `wrangler.toml` 的 `name = "kingcola"` 一致，否则构建失败（官方明写的限制） |
| ⚠️ 前置③ | 6 个**运行期**密钥（SESSION_SECRET / STUDENT_SESSION_SECRET / QR_SIGN_SECRET / SSO_CLIENT_SECRET / RECOVERY_TOKEN / SMTP_PASSWORD）要配在 Dashboard 的 Environment variables；Build variables 是另一套、只在构建期可见 |
| Node 版本 | 构建镜像（Ubuntu 24.04）预装 **22.23.2 与 24.18.0，默认 24.18.0**；本项目本地就是 22.23.2 → 建议显式钉：Build variable `NODE_VERSION=22` 或根目录放 `.nvmrc`（内容 `22`）。npm 固定 10.9.2，无覆盖变量 |
| 额度 | 免费 3000 构建分钟/月、并发 1、单次超时 20 分钟（本项目一次 1–3 分钟，够用） |
| ❌ 数据库迁移 | Workers Builds **不会**跑 D1 迁移，仍要手动 `npm run db:migrate:remote`；而且自动生成的 API token 权限只有 Workers Scripts / KV / R2 edit + Worker Routes，**没有 D1 edit**，把迁移塞进部署命令会因权限失败（本项目也刻意不用 `d1 migrations apply`） |
